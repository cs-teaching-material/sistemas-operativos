Bloque A · Conceptos Fundamentales

Definiciones de Primera Aparición

  • Virtualización: Tecnología que crea representaciones basadas en software de recursos físicos (servidores, almacenamiento, redes).
  • Host (Anfitrión): El equipo físico real que provee los recursos de hardware subyacentes.
  • Guest (Invitado o VM): El sistema operativo "virtual" que corre encima y cree poseer hardware físico dedicado.
  • Hypervisor (VMM): El software especializado ("Virtual Machine Monitor") encargado de repartir el hardware real entre las diferentes VMs.

El engaño perfecto

El Guest (la Máquina Virtual) envía instrucciones al CPU pensando que está solo. El Hypervisor intercepta, traduce y programa esas instrucciones en el CPU real de manera segura.

Bloque B · Hypervisor Tipo 1 (Bare-Metal)

La Virtualización de Grado Empresarial

  • Ejecución Directa: El Hypervisor se instala directamente sobre el hardware desnudo, en lugar de instalar Windows o Linux primero.
  • Sin SO Intermediario: Elimina la latencia de pasar por un sistema operativo base.
  • El Hypervisor Tipo 1 ES, en esencia, un kernel operativo altamente especializado y minimalista.
  • Casos de Uso: Datacenters, Cloud (AWS, Azure), Servidores corporativos de alta densidad.

Ejemplos Clásicos

  • VMware ESXi / vSphere.
  • Microsoft Hyper-V Server.
  • Proxmox VE (KVM basado en Debian).
  • Xen.

Poseen máxima eficiencia; no desperdician RAM dibujando GUIs innecesarias localmente.

Bloque C · Hypervisor Tipo 2 (Hosted)

Virtualización Doméstica y Desarrollo

  • Con SO Intermediario: Se instala como una aplicación normal encima de un Sistema Operativo existente (tu Windows, macOS o Linux).
  • Sobrecarga (Overhead): Las instrucciones del Guest pasan por el Hypervisor y luego al SO Host antes de tocar el hardware físico.
  • Al depender del SO Host, hereda sus vulnerabilidades y latencias.
  • Casos de Uso: Aulas de clase, laboratorios locales de desarrollo, pruebas de software (Testing).

Ejemplos Clásicos

  • Oracle VirtualBox.
  • VMware Workstation Player.
  • Parallels Desktop (macOS).

Su ventaja radical es la conveniencia: puedes probar Linux en una ventana mientras mantienes Spotify abierto en tu Windows Host.

Concepto Avanzado · Aceleración por Hardware (VT-x / AMD-V)

Cuando la CPU entiende la ilusión

  • Inicialmente, los Hypervisors atrapaban instrucciones privilegiadas del Guest y las emulaban (lentísimo).
  • Intel VT-x y AMD-V: Modificaciones en la silicona (CPU real) creadas para Virtualización.
  • Añaden un nivel de ejecución extra (Anillos de privilegio bajo cero / Ring -1) exclusivo para el Hypervisor.
  • Permiten que las instrucciones de la Máquina Virtual corran al ritmo veloz del procesador físico.

Configuración Crítica

Si la Virtualización no está activada en la BIOS/UEFI de la máquina host, los Hypervisores de 64 bits modernos fallarán o no permitirán instalar sistemas de 64 bits en el guest.

Concepto Avanzado · Virtualización de RAM

Traducción de Direcciones (EPT/SLAT)

  • Un SO normal traduce su Memoria Virtual a Memoria Física mediante la Tabla de Páginas (Unidad 2).
  • En una VM, la "Memoria Física" del Guest sigue siendo solo Memoria Virtual provista por el Host.
  • Se requiere Traducción de Dos Niveles: Virtual(Guest) → Física(Guest) → Física(Host).
  • Las características SLAT (Second Level Address Translation) hacen este paso dual directamente por hardware.

Isla de RAM (Aislamiento total)

Si asignamos 4GB de RAM a una VM, el OS Host reserva y encapsula 4GB estrictos. El Guest no puede, matemáticamente, leer fuera de esos 4GB hacia la memoria del Host.

SLAT y EPT12 / 25
Abstracción Transversal · Redes Virtuales

¿Cómo el Guest obtiene Internet?

  • El Hypervisor crea una Tarjeta de Red Virtual (vNIC) y la expone al Guest como hardware oficial.
  • Modo NAT (Network Address Translation): La VM obtiene una IP privada (10.0.2.15). El Host actúa como un Router para ella. Salida sí, entrada difícil.
  • Modo Bridged (Adaptador Puente): La VM se inyecta directamente a la red física de la oficina. Obtiene IP del DHCP oficial del edificio.

Capa 2 y Switches Virtuales

El software incluye Switches por software. Múltiples VMs pueden hablar entre sí en una red "Host-Only" aislada por completo del exterior, requerida para simulaciones de ciberataques seguras.

Construcción y Límite de Recursos en VM

Enunciado: Crear una configuración inicial segura para un laboratorio en VirtualBox / Hyper-V validando los límites de hardware del Host.

  1. Abrir Task Manager local e inspeccionar (Cores Físicos y RAM total libre).
  2. Crear una nueva Máquina en Hypervisor (Tipo 2).
  3. Asignar un máximo del 50% de Cores físicos y 50% de RAM libre al Guest.
  4. Configurar red tipo NAT y provisionar un Disco Duro VDI de expansión dinámica.

Actividad formativa. No evaluativa.

Regla de Oro en Lab:

Nunca asignar todos tus CPU cores a la VM. Si tienes 4 Cores nativos, asigna máximo 2. Si asignas los 4, el SO Host peleará con el Guest por tiempo de procesador, congelando el equipo.

Configuración Base (Práctica 1)14 / 25
Desarrollo y Justificación

Decisiones en el dimensionamiento

  • Límite CPU (50%): El Hypervisor es un proceso del Host. Si le damos todo el CPU a la VM, el Host no tendrá CPU para ejecutar sus instrucciones ni procesar el redibujado de la pantalla.
  • Expansión de Disco:
    • Dinámico: Archivo ligero que crece bajo demanda. Ahorra espacio físico en tu laptop.
    • Fijo: Bloquea todos los gigas desde el segundo 1. Otorga mayor rendimiento transaccional.
# Ejemplo de asignación correcta Host real: i5 4 Cores / 16GB RAM Guest Win10: - CPU: 2 Cores - RAM: 4096 MB (4GB) - Red: NAT - Disco VDI: 50GB (Dinámico) Guest Ubuntu Server CLI: - CPU: 1 Core - RAM: 1024 MB (1GB) - Red: NAT

Simbiosis Host-Guest

Guest Additions / VMware Tools

  • Por defecto, el Hypervisor inyecta hardware "genérico y estándar" (VGA de 1995, ratón PS/2 estándar).
  • El Problema: Pantallas pequeñas, sin aceleración de video, puntero "atrapado" operativamente.
  • La Solución: Instalación de aplicaciones dentro del SO Guest que proveen drivers paravirtualizados optimizados.

Ventajas inmediatas:

  • Portapapeles compartido (Copy-Paste).
  • Carpetas compartidas nativas.
  • Aceleración gráfica 3D y Drag & Drop.
Guest Additions16 / 25
Cápsulas del Tiempo

Snapshots y Checkpoints

  • Permite congelar el estado exacto de una VM (disco rígido y RAM) en el tiempo.
  • Al hacerlo, el disco original se vuelve de solo lectura, y todos los cambios futuros se guardan en un archivo "diferencial" (Delta).
  • Restauración: Si descartamos el archivo Delta, la máquina viaja al pasado, borrando cualquier daño o virus infectado.

Atención Operativa

Los Snapshots NO son Backups. Dependen del disco original inmutable. Solo se usan para regresiones por cambios temporales cortos.

Desarrollo y Justificación

¿Por qué la recuperación es instantánea?

  • Destruir el SO del Guest solo sobreescribe registros en el archivo diferencial en el disco de tu host de Windows.
  • Al dar click en "Restaurar", el Hypervisor tira el archivo a la basura y reconecta el cabezal de lectura al disco base inmutable.
  • Esto nos habilitará posteriormente a probar configuraciones de "Hardening" y testear "Malware" en las sesiones 22 y 23.

El costo de la Virtualización (Overhead)

La penalidad matemática

  • Abstraer componentes (pantalla virtual, disco virtual) requiere procesos intermedios.
  • Cada vez que una VM tipo 2 escribe en su SSD virtual, el sistema Guest llama a su kernel, el Hypervisor lo procesa, el Sistema Host Windows lo recibe y luego va al hardware real.
  • Por cada salto en esta cadena, se pierde tiempo, llegando a un 5% y 15% de reducción de rendimiento (overhead).

Operativa · Troubleshooting Diario

Diagnóstico en el mundo real

  • "La VM está increíblemente lenta y su disco al 100%"
    Causa: Falta de RAM en el Guest o hiper-asignación de CPU.
  • "La VM da Loop infinito de Boot"
    Causa: El controlador de almacenamiento en la config virtual (SATA vs IDE) o el estándar de firmware (BIOS vs UEFI) no coincide.
  • "No hay internet en el Guest"
    Causa: Cable Red Virtual desconectado en opciones, o protección corporativa bloqueando modo Puente (Bridged).

Reflexión Crítica

Dada la inmutabilidad de la virtualización, cuando falla la máquina, el error humano suele residir en los ajustes perimetrales proporcionados por el Hypervisor, rara vez en el sistema operativo Guest de base.

Portabilidad Pura · El estándar OVA

Llevando Servidores en un Pendrive

  • Open Virtualization Format (OVF): Estándar abierto mantenido por la DMTF para compartir de forma segura Máquinas Virtuales pre-configuradas.
  • Integra discos comprimidos (`.vmdk`) y manifiestos de hardware (`.ovf`) validados criptográficamente.
  • OVA (Open Virtual Appliance): Es el OVF consolidado en un único mega-archivo.
  • Permite configurar un ecosistema robusto en un PC local, mandarlo por red, e importarlo con doble click en otra infraestructura a miles de kilómetros.

Síntesis Técnica Final

Lo más destacado de Virtualización

  • Virtualizar es abstraer y aislar.
  • Tipo 1: Profesional de Datacenter, enraizado al hardware (ESXi, Proxmox).
  • Tipo 2: Laboratorio / Desktop, vive encima de su OS Windows/Mac.
  • Los límites de hardware virtualizado protegen el equipo Host de las negligencias probadas en la VM.
  • Snapshots inician la base del versionamiento temporal indispensable en Ciberseguridad.

¿Es esto óptimo para todo?

  • Importar una VM pesa Gigabytes. Arrancar un Kernel toma preciosos segundos, y carga procesos del SO de fondo inútiles.
  • En Microservicios y DevOps, no se toleran estas latencias ni ese consumo excesivo de disco.
  • Virtualizar hardware entero quedó anticuado para desplegar aplicaciones web atómicas.
