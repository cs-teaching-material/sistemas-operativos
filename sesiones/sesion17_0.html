Bloque A · El proceso: unidad de ejecución del SO

Definiciones de primer uso

  • Proceso: instancia en ejecución de un programa. Un mismo programa puede originar múltiples procesos simultáneos e independientes.
  • PID (Process Identifier): número entero único que el kernel asigna a cada proceso al crearlo. Nunca se repite mientras el proceso vive.
  • PPID (Parent PID): PID del proceso que lo creó. Todo proceso tiene un padre; el proceso raíz es init / systemd con PID 1.
  • Señal (signal): notificación asíncrona enviada por el kernel o un proceso a otro proceso para indicarle que ocurrió un evento.

El árbol de procesos

Todos los procesos del sistema forman un árbol con systemd (PID 1) en la raíz. Cuando el Shell ejecuta un comando, ese comando es un hijo del Shell, que a su vez es hijo del terminal emulator, que es hijo de systemd.

Esto explica por qué al cerrar una terminal los procesos que lanzaste desde ella también mueren: el kernel propaga la señal de muerte a los hijos.

¿Por qué importa el estado D?

Un proceso en estado D no puede ser terminado con kill -9. Solo se elimina cuando completa la operación de E/S o al reiniciar. Ver muchos procesos en D es síntoma de un problema de disco o sistema de archivos.

Bloque B · Señales y kill: recuperar el control

Señales más usadas

NúmeroNombreEfecto
1SIGHUPRecarga configuración (hang up). Muchos daemons lo interpretan como "relee tu config".
2SIGINTInterrupción. Equivale a Ctrl+C en el terminal.
15SIGTERMTerminación elegante. El proceso puede limpiar recursos antes de salir. Es la señal por defecto de kill.
9SIGKILLTerminación inmediata e incondicional. El kernel la ejecuta; el proceso no puede ignorarla ni capturarla.
19SIGSTOPPausa el proceso (equivale a Ctrl+Z). No se puede ignorar.
18SIGCONTReanuda un proceso detenido con SIGSTOP.

Regla de oro: SIGTERM antes que SIGKILL

Siempre intenta primero kill PID (SIGTERM). Si el proceso no responde en ~5 segundos, usa kill -9 PID. SIGKILL no da tiempo al proceso de cerrar conexiones, escribir en disco o liberar locks: puede dejar datos corruptos.

# Señal por defecto (SIGTERM = 15) kill 6310 # Terminación forzada (SIGKILL = 9) kill -9 6310 # Por nombre de proceso (mata todos los matches) killall firefox

Salida esperada

Respuestas

  3. SIGTERM pide al proceso que termine limpiamente. El kernel retira el PID de la tabla de procesos; la próxima ejecución de ps ya no lo encuentra.

Bloque C · El pipe: conectar procesos en cadena

¿Qué es un pipe?

Un pipe (|) es un mecanismo del kernel que conecta el stdout de un proceso directamente con el stdin del siguiente, sin escribir nada en disco. Los dos procesos corren concurrentemente: el primero produce datos mientras el segundo los consume.

# Sin pipe: dos pasos, archivo temporal ps aux > /tmp/procesos.txt grep bash /tmp/procesos.txt # Con pipe: un paso, sin disco ps aux | grep bash # Cadena de tres comandos ps aux | grep bash | wc -l

Filosofía Unix

"Escribe programas que hagan una cosa y la hagan bien. Escribe programas que trabajen juntos."

— Doug McIlroy, inventor del pipe Unix (Bell Labs, ~1973)

El pipe es la herramienta que hace posible esa filosofía: cada comando es una pieza especializada; la cadena es el sistema completo.

Bloque C · Pipelines aplicados a administración de sistemas

Preguntas que responde un pipeline

# ¿Cuántos procesos corre el usuario "root"? ps aux | grep ^root | wc -l # Los 5 procesos que más CPU consumen ahora ps aux | sort -k3 -rn | head -6 # Los 5 procesos que más RAM ocupan ps aux | sort -k4 -rn | head -6 # ¿Cuántas veces aparece "error" en el log de hoy? grep -i "error" /var/log/syslog | wc -l # Usuarios únicos con sesión activa who | awk '{print $1}' | sort -u

Patrón de construcción

Cuando construyes un pipeline, empieza por el primer comando y verifica su salida antes de añadir el siguiente. Construye de izquierda a derecha, una pieza a la vez:

ps aux ps aux | sort -k3 -rn ps aux | sort -k3 -rn | head -6

Práctica guiada 2 · Pipeline de diagnóstico de servidor

Escenario: el servidor está lento

Un servidor de producción responde con lentitud. Debes construir un informe rápido usando solo la línea de comandos.

# 1. ¿Cuántos procesos están corriendo en total? ps aux | wc -l # 2. Top 5 procesos por CPU (excluyendo cabecera) ps aux | sort -k3 -rn | head -6 # 3. ¿Hay algún proceso zombie? ps aux | grep " Z " # 4. Cuántas líneas de error hay en el log del sistema grep -i "error" /var/log/syslog 2>/dev/null | wc -l # 5. Guarda el informe completo en ~/informe_procesos.txt { echo "=== Procesos totales ===" ps aux | wc -l echo "=== Top 5 CPU ===" ps aux | sort -k3 -rn | head -6 echo "=== Zombies ===" ps aux | grep " Z " } > ~/informe_procesos.txt cat ~/informe_procesos.txt

Preguntas de análisis

  1. El paso 1 devuelve un número mayor al de procesos reales. ¿Por qué?
  2. ¿Por qué el sort -k3 -rn ordena de mayor a menor CPU?
  3. Si el paso 3 no devuelve nada, ¿hay un error o simplemente no hay zombies?

Conservar informe_procesos.txt como evidencia de práctica formativa en clase (actividad no evaluativa).

Solución guiada 2

Contenido esperado de informe_procesos.txt

=== Procesos totales === 187 === Top 5 CPU === USER PID %CPU %MEM COMMAND mysql 821 8.2 5.3 mysqld www-data 455 5.1 2.1 nginx: worker root 312 3.7 0.2 sshd: estudiante root 1 0.2 0.1 /sbin/init root 234 0.3 0.4 /usr/lib/systemd/... === Zombies === (vacío si no hay zombies)

Respuestas

  1. ps aux | wc -l cuenta también la línea de cabecera de ps. El número real de procesos es el resultado menos 1. Para excluirla: ps aux | tail -n +2 | wc -l.
  2. -r invierte el orden (de menor a mayor pasa a ser mayor a menor). -n interpreta los valores como números en lugar de texto: sin -n, "10" aparecería antes que "9" (comparación de caracteres).
  3. Salida vacía significa que no hay procesos en estado Z: grep devuelve código de error 1, pero no imprime nada. Ausencia de salida = sin zombies = todo bien.

Errores frecuentes y cómo corregirlos
ErrorCausaCorrección
Usar kill -9 directamente sin intentar SIGTERM primero El estudiante cree que SIGKILL es "más seguro" porque garantiza la muerte del proceso. SIGTERM primero; esperar ~5 s; solo entonces usar kill -9. SIGKILL puede dejar datos corruptos si el proceso tenía transacciones abiertas.
ps aux | grep proceso devuelve la línea del propio grep El proceso grep aparece en la lista porque su COMMAND contiene el patrón buscado. Usar grep -v grep al final: ps aux | grep nginx | grep -v grep. O el truco de corchetes: grep [n]ginx.
sort -k3 -n da orden incorrecto (0.1 antes que 9.8) Los valores de CPU con punto decimal se leen mal si no se especifica locale decimal. Agregar -t' ' o usar sort -k3 -rn y verificar que el separador de columnas es espacio. En muchos sistemas funciona directamente.
Confundir VSZ con RSS en ps aux El estudiante cree que VSZ es la RAM real usada. VSZ = memoria virtual total (incluye zonas aún no cargadas en RAM). RSS = lo que realmente está en RAM ahora. Para diagnosticar presión de memoria, mirar RSS y %MEM.
El pipe no parece funcionar: command1 | command2 no muestra nada command1 produce salida en stderr en lugar de stdout, y el pipe solo conecta stdout. Redirigir stderr al pipe: command1 2>&1 | command2. O usar |& en bash como atajo equivalente.

Síntesis técnica · Lo esencial de hoy

Mapa mental en 5 puntos

  • Proceso y PID: toda ejecución tiene un identificador único; todos los procesos forman un árbol cuya raíz es systemd (PID 1).
  • Estados: R (ejecutando), S (durmiendo), D (E/S irrompible), Z (zombie), T (detenido). El estado D no acepta señales.
  • kill y señales: SIGTERM (15) es la vía elegante; SIGKILL (9) es el último recurso. Siempre intentar SIGTERM primero.
  • Pipe (|): conecta stdout de un proceso con stdin del siguiente, sin pasar por disco. Los procesos corren concurrentemente.
  • grep / sort / wc: los tres filtros fundamentales. Combinados en un pipeline responden cualquier pregunta de diagnóstico sobre el sistema.

Próxima sesión: Seguridad de Archivos y Permisos POSIX

Hoy vimos que algunos procesos corren como root y otros como usuarios normales. Esa distinción no es arbitraria: controla quién puede leer, escribir o ejecutar cada archivo del sistema.

  • chmod: modificar permisos de lectura, escritura y ejecución.
  • chown: cambiar el propietario y grupo de un archivo.
  • Notación octal de permisos: por qué 755 significa lo que significa.
  • Principio de Menor Privilegio (PoLP): por qué nunca se trabaja como root por defecto.
