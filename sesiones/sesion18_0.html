Bloque A · Control Discrecional de Acceso (DAC)

Definiciones

  • DAC: el propietario del recurso decide qué permisos otorga a los demás. Modelo estándar POSIX.
  • Dueño: usuario que creó el archivo. El kernel registra su UID en el i-nodo.
  • Grupo: conjunto de usuarios. Cada archivo pertenece a exactamente un grupo (GID).
  • Otros: cualquier usuario que no es ni el dueño ni miembro del grupo.

¿Por qué tres niveles?

Diseño de Bell Labs (1969): tres sujetos para cubrir la mayoría de casos sin complejidad excesiva.

  1. El creador necesita acceso completo a su propio archivo.
  2. Un equipo de trabajo comparte ciertos archivos.
  3. El resto del sistema debe tener acceso mínimo o nulo.

Orden real de decisión en el kernel: primero compara UID (dueño), si no coincide compara GID (grupo), y solo si ambos fallan aplica "otros". No mezcla bloques.

Esto permite auditar con precisión: al conocer la identidad efectiva del proceso, puedes predecir exactamente qué triada usará el kernel.

Para casos más finos: ACL (Access Control Lists), tema de cursos avanzados.

Bloque A · Significado de r, w, x según el tipo de objeto
PermisoSobre un archivoSobre un directorio
r (read · 4) Leer el contenido (cat, less, copiar como origen). Listar el contenido con ls. Sin r: "Permission denied".
w (write · 2) Modificar el contenido. No implica poder borrar el archivo: eso depende del w del directorio padre. Crear, renombrar o borrar archivos dentro. Sin w en el dir, touch y rm fallan.
x (execute · 1) Ejecutar el archivo como programa. Sin x el Shell no puede lanzarlo. Entrar al directorio con cd. También necesario para acceder a archivos por ruta.

Distinción crítica: borrar un archivo no requiere w sobre el archivo sino w+x sobre el directorio que lo contiene. El archivo es solo una entrada en el directorio.

Bloque B · chmod: modificar permisos

Dos formas de usar chmod

# Notación octal (estado final exacto) chmod 755 script.sh # rwxr-xr-x chmod 644 config.conf # rw-r--r-- chmod 600 id_rsa # rw------- chmod -R 755 /var/www/html # Notación simbólica (modificar un bit) # u=dueño g=grupo o=otros a=todos # +=añadir -=quitar ==exacto chmod u+x script.sh chmod g-w archivo.txt chmod o=r reporte.pdf chmod ug=rw,o=r notas.md

¿Octal o simbólico?

  • Octal: establecer el estado final exacto. Más rápido en scripts.
  • Simbólico: modificar solo un bit sin afectar los demás. Más legible interactivamente.

Precaución operativa: en árboles grandes, evita aplicar chmod -R sin criterio sobre enlaces simbólicos. Para despliegues seguros, separa directorios y archivos con find -type d/-type f y usa a+rX cuando quieras dar x solo a directorios (y a ejecutables ya marcados).

Solo el dueño (o root) puede cambiar los permisos de un archivo.

Bloque B · chown y chgrp: cambiar propietario

chown — Change Owner

# Solo el dueño chown maria reporte.txt # Dueño y grupo simultáneamente chown maria:devs reporte.txt # Recursivo (servidor web) chown -R www-data:www-data /var/www/html # Verificar ls -l reporte.txt

chgrp — Change Group

# Cambiar solo el grupo chgrp devs reporte.txt # Equivalente con chown chown :devs reporte.txt

Restricción clave: solo root puede cambiar el dueño a otro usuario. Un usuario puede cambiar el grupo a uno del que sea miembro.

Bloque C · Principio de Menor Privilegio (PoLP)

Definición y fundamento

PoLP: cada usuario, proceso o servicio debe tener exactamente los permisos necesarios para su función y ninguno más.

  • Contención: un proceso comprometido solo accede a lo que podía tocar.
  • Auditabilidad: menos permisos = menos vías = más fácil rastrear cambios no autorizados.
  • Error accidental: sin permiso de escritura, un bug no puede borrar datos.

Antipatrón: chmod 777 "para que funcione"

El error más común en estudiantes y producción. Al dar 777 a un directorio web:

  • Cualquier usuario del sistema puede leer los archivos.
  • Un proceso comprometido puede escribir y ejecutar código malicioso.
  • El servidor se vuelve vector de ataque para el resto del sistema.

Regla: si 777 "lo arregla", el problema es otro. El dueño o el grupo están mal asignados.

Bloque C · Bits especiales: SUID, SGID y Sticky

SUID — Set User ID

Cuando un binario tiene SUID activo, el proceso hereda el UID del dueño del archivo. La s reemplaza la x del dueño en ls -l.

ls -l /usr/bin/passwd -rwsr-xr-x 1 root root /usr/bin/passwd # passwd corre como root aunque lo lance # un usuario normal. Puede escribir en # /etc/shadow (root:shadow 640).

SGID y Sticky bit

SGID: aplica el GID del archivo. En directorios, archivos creados dentro heredan el grupo.

ls -l /usr/bin/write -rwxr-sr-x 1 root tty (SGID activo)

Sticky bit (t): solo el dueño del archivo puede borrarlo aunque otros tengan w en el directorio.

ls -ld /tmp drwxrwxrwt 10 root root /tmp

Lectura fina de letras especiales: s/t minúscula indica bit especial + x activo. S/T mayúscula indica bit especial sin x, configuración válida pero poco útil en la mayoría de casos.

Bloque C · umask: los permisos por defecto al crear archivos

¿Por qué los archivos no nacen con 777?

El kernel parte de un máximo y resta la umask. La umask bloquea ciertos bits automáticamente.

# Ver la umask actual umask 0022 # valor más común # Archivo nuevo: # máximo 666 → rw-rw-rw- # umask 022 → ---w--w- (bloqueados) # resultado 644 → rw-r--r-- # Directorio nuevo: # máximo 777 - umask 022 = 755 # Cambiar umask en la sesión actual umask 027 # archivos: 640 · dirs: 750

umask 027 en servidores

Con umask 022 (defecto), "otros" pueden leer archivos nuevos. En producción conviene 027: archivos nacen con 640 (solo dueño y grupo leen) y directorios con 750. Los archivos de configuración no son legibles por usuarios no autorizados desde su creación.

# Vista simbólica de máscara efectiva umask -S u=rwx,g=rx,o= # Regla operativa archivos: 666 - umask directorios: 777 - umask

Práctica guiada 2 · Auditoría de permisos de un servidor web

Escenario: heredaste un servidor con 777

# 1. Simular el problema mkdir -p ~/webroot/{html,logs,conf} touch ~/webroot/html/index.html touch ~/webroot/conf/app.conf touch ~/webroot/logs/access.log chmod -R 777 ~/webroot # 2. Auditar: archivos world-writable find ~/webroot -perm -o+w -ls # 3. Corregir con PoLP find ~/webroot/html -type d -exec chmod 755 {} \; find ~/webroot/html -type f -exec chmod 644 {} \; chmod 750 ~/webroot/conf chmod 640 ~/webroot/conf/app.conf chmod 750 ~/webroot/logs chmod 640 ~/webroot/logs/access.log chmod 755 ~/webroot # 4. Verificar y guardar evidencia find ~/webroot -perm -o+w -ls > ~/auditoria_permisos.txt

Preguntas de análisis

  1. ¿Por qué usamos -type d y -type f por separado en el paso 3?
  2. ¿Qué significa el flag -perm -o+w en find?
  3. ¿Por qué el log tiene 640 y no 644?
Práctica 2 · Auditoría y corrección de permisos18 / 22
Solución guiada 2

Estado final esperado

drwxr-xr-x webroot/ drwxr-xr-x webroot/html/ -rw-r--r-- webroot/html/index.html drwxr-x--- webroot/conf/ -rw-r----- webroot/conf/app.conf drwxr-x--- webroot/logs/ -rw-r----- webroot/logs/access.log # Paso 4: sin salida = sin world-writable # cat ~/auditoria_permisos.txt → vacío

Respuestas

  1. -type d y -type f por separado: los directorios necesitan x para poder entrar con cd. Un directorio 644 no permite entrada. Los HTML no son ejecutables, 644 es correcto para ellos.
  2. -perm -o+w: el guión es el modo "al menos estos bits". Encuentra cualquier archivo donde el bit de escritura para "otros" esté activo.
  3. Los logs tienen IPs de clientes, rutas internas y mensajes de error que revelan la arquitectura. Bajo PoLP, solo el proceso servidor (dueño) y los administradores (grupo) acceden.

Síntesis técnica · Lo esencial de hoy

Mapa en 6 puntos

  • DAC: el dueño decide. Tres sujetos: dueño, grupo, otros.
  • 10 caracteres: tipo (1) + dueño (3) + grupo (3) + otros (3). r=4, w=2, x=1.
  • Octal: suma de bits por bloque. rwxr-xr-x = 755.
  • chmod / chown: dos herramientas, dos tareas distintas. Solo root cambia el dueño a otro usuario.
  • PoLP: permiso mínimo necesario. 777 nunca es la solución correcta.
  • SUID: el proceso hereda el UID del dueño del binario. Base de sudo y passwd.

Competencia adquirida

Puedes heredar un servidor con permisos incorrectos, auditarlo con find -perm, entender por qué cada archivo tiene los permisos que tiene, y corregirlos aplicando PoLP sin romper el sistema.

Próxima sesión: Bases de Scripting y Automatización

Hoy aplicamos permisos manualmente. En producción, miles de archivos necesitan permisos correctos después de cada despliegue. La solución es un script.

  • Variables de entorno y Shell: parametrizar comportamiento.
  • Condicionales (if, test): ejecutar solo si se cumple una condición.
  • Bucles (for, while): aplicar operaciones a múltiples archivos.
  • Shebang (#!/bin/bash): declarar el intérprete del script.

Preparación sugerida

echo '#!/bin/bash echo "Hola desde mi primer script" echo "Usuario: $(whoami)" echo "Directorio: $(pwd)"' > ~/hola.sh chmod 755 ~/hola.sh ./hola.sh
