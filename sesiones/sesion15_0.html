Terminos de Primera Aparicion

Shell, CLI y GUI

  • Shell: interprete que traduce comandos en acciones ejecutables.
  • CLI: interfaz textual de operacion.
  • GUI: interfaz grafica de operacion.

Terminal, Prompt, Kernel, Syscall

  • Terminal: aplicacion que hospeda una shell.
  • Prompt: estado de espera listo para comando.
  • Kernel: nucleo de control de recursos.
  • Syscall: solicitud formal de servicio al kernel.

Error comun: confundir terminal con shell. La terminal es el contenedor visual; la shell es quien interpreta.

Glosario inicial4 / 20
Flujo de una Orden: Del Teclado al Kernel

Lectura tecnica

  1. El usuario emite orden.
  2. La shell parsea sintaxis y argumentos.
  3. Invoca syscall al kernel si necesita recursos.
  4. Kernel responde con datos o error.
  5. La shell renderiza salida.

Prompt y Lectura de Contexto

Datos minimos que siempre debes leer

  • Usuario activo.
  • Ruta actual (CWD).
  • Tipo de shell.
  • Nivel de privilegio.
usuario@equipo:~$ whoami usuario usuario@equipo:~$ pwd /home/usuario

Glosario tecnico

  • CWD: carpeta donde corren los comandos.
  • HOME: ruta base del usuario.
  • PATH: rutas de busqueda de ejecutables.
  • ROOT: cuenta de maximo privilegio.

Opcion Inmediata: JSLinux Sin Cuenta

Paso a paso (menos de 30 segundos)

  1. Abrir bellard.org/jslinux en el navegador.
  2. Click en Alpine Linux stable (ttyS0).
  3. Esperar ~5 segundos a que cargue el sistema.
  4. La terminal aparece lista sin instalar nada.
  5. Ejecutar los comandos del laboratorio.
whoami pwd uname -a echo $SHELL

Que tener en cuenta

  • Funciona desde cualquier equipo con navegador.
  • Sin instalacion ni permisos especiales en el equipo.
  • Limitacion: el entorno se reinicia al cerrar la pestana.
  • Evidencia: copiar texto de la terminal antes de cerrar, o captura de pantalla.

JSLinux emula Alpine Linux. Los comandos base de bash funcionan igual que en Ubuntu.

Opcion Persistente: GitHub Codespaces

Configuracion inicial (una sola vez)

  1. Crear cuenta gratuita en github.com.
  2. Ir a github.com/codespaces.
  3. Click New codespace y elegir plantilla Blank.
  4. Esperar ~30 segundos mientras inicia Ubuntu.
  5. Terminal bash disponible inmediatamente.

Plan gratuito: 60 horas al mes y 15 GB de almacenamiento. Suficiente para toda la unidad.

Por que Codespaces para el semestre

  • Ubuntu 22.04 completo con bash.
  • Archivos y carpetas persisten entre sesiones.
  • Accesible desde cualquier equipo o red.
  • No depende del equipo del aula ni de permisos de instalacion.

Flujo de Trabajo por Sesion en Codespaces

Estructura recomendada por sesion

mkdir -p ~/so_u3/sesion15/comandos ~/so_u3/sesion15/evidencias cd ~/so_u3/sesion15 # guardar diagnostico whoami > evidencias/evidencia_s15.txt uname -a >> evidencias/evidencia_s15.txt echo $SHELL >> evidencias/evidencia_s15.txt ls -R ~/so_u3

Regla de persistencia

  • Los archivos quedan guardados automaticamente en el codespace.
  • Al abrir Codespaces la proxima sesion, todo sigue donde lo dejaste.
  • Si el codespace expira (30 dias sin uso), GitHub avisa por correo.

Para redundancia extra: copiar archivos a un repositorio Git al final de cada sesion.

Laboratorio 2: Solucion de Referencia

Bash · valido en JSLinux y en Codespaces

mkdir -p ~/so_u3/sesion15/comandos ~/so_u3/sesion15/evidencias cd ~/so_u3/sesion15 { echo "--- identidad ---" whoami echo $SHELL echo "--- contexto ---" pwd echo "--- sistema ---" uname -a } > evidencias/evidencia_s15.txt printf "whoami\necho \$SHELL\npwd\nuname -a\n" > comandos/comandos_s15.txt ls -R ~/so_u3

Diferencia entre herramientas

  • JSLinux: copiar la salida antes de cerrar la pestana; no persiste.
  • Codespaces: el archivo queda guardado automaticamente; no hace falta copiar.
cat evidencias/evidencia_s15.txt

Criterio: el archivo debe contener usuario, shell activa, ruta y version de kernel.
