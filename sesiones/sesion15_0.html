Bloque B · Intérpretes de comandos más usados

Familia POSIX (Unix/Linux/macOS)

  • sh (Bourne Shell, 1979): el estándar mínimo. Presente en todos los sistemas POSIX.
  • bash: el más común en Linux. Añade historial, autocompletado y scripts avanzados.
  • zsh: extensión de bash con plugins (Oh My Zsh). Predeterminado en macOS desde Catalina.
  • dash: shell minimalista y rápido. Usado en scripts de arranque de Ubuntu.

Entorno Windows

  • cmd.exe: heredero del DOS. Comandos propios (dir, copy). Sin POSIX nativo.
  • PowerShell: orientado a objetos. Los pipelines pasan objetos .NET, no solo texto.
  • WSL2: kernel Linux real dentro de Windows. Permite bash y herramientas GNU directamente.

Bloque B · ¿Qué sucede internamente al ejecutar un comando?

Flujo completo de ls -l /home

  1. Lectura: el terminal emulator captura la cadena y la pasa al Shell.
  2. Lexing: el Shell tokeniza (ls=programa, -l=flag, /home=argumento).
  3. Búsqueda: el Shell consulta PATH y localiza /usr/bin/ls.
  4. Fork + exec: crea un proceso hijo (fork) y lo reemplaza con el binario (execve).
  5. Kernel: resuelve permisos, lee el directorio del sistema de archivos y devuelve los datos.
  6. Salida: el proceso hijo escribe en stdout (fd 1); el terminal lo muestra.

Punto de enlace con la Unidad 2

El paso 5 usa exactamente las estructuras de i-nodos y directorios de Ext4/NTFS. El kernel invoca el VFS (Virtual File System) para abstraer el sistema de archivos real del disco.

Bloque B · Variables de entorno: el caso de PATH

¿Qué es PATH?

Variable de entorno: par clave=valor inyectado automáticamente en cada proceso nuevo. PATH es la lista de directorios donde el Shell busca binarios cuando se escribe un comando sin ruta absoluta.

$ echo $PATH /usr/local/sbin:/usr/local/bin:/usr/bin:/bin # El Shell busca izquierda→derecha. # El primero que encuentre el binario gana.

Implicación de seguridad

Un atacante que inserte un directorio controlado al inicio del PATH puede hacer que el sistema ejecute su propio binario malicioso en lugar del legítimo. Se abordará en profundidad en la sesión de Hardening (sesión 23).

Bloque C · Flujos estándar de E/S

stdin, stdout, stderr

Todo proceso Unix hereda tres descriptores de archivo abiertos desde su creación:

  • stdin (fd 0): entrada estándar. Por defecto, el teclado.
  • stdout (fd 1): salida estándar. Por defecto, la pantalla.
  • stderr (fd 2): salida de errores. Por defecto, también la pantalla, pero separada de stdout.

El Shell puede redirigir cualquiera de estos flujos hacia archivos o hacia otros procesos (pipes).

¿Por qué dos flujos de salida?

Separar stdout y stderr permite procesar la salida útil sin que los mensajes de error la contaminen. Ejemplo: ls /no-existe 2>/dev/null silencia el error y solo muestra los resultados válidos.

Bloque C · Redirección de flujos

Operadores de redirección

# stdout a archivo (sobrescribe) ls -l /home > listado.txt # stdout y agregar (no sobrescribe) echo "nueva línea" >> listado.txt # stderr a archivo ls /no-existe 2> errores.txt # stderr y stdout al mismo archivo ls /home /no-existe > todo.txt 2>&1 # Descartar stderr ls /no-existe 2>/dev/null

Regla de lectura

2>&1: "redirige fd 2 (stderr) al mismo destino donde apunta fd 1 (stdout)". El orden importa: primero se establece el destino de fd 1 y luego se une fd 2 a él.

/dev/null es el sumidero del sistema: todo lo escrito ahí desaparece sin ocupar espacio en disco.

Solución guiada 2

Contenido esperado de diagnostico.txt

Shell: /bin/bash | Usuario: estudiante PATH=/usr/local/sbin:/usr/local/bin:/usr/bin:/bin ls: cannot access '/root': Permission denied

La tercera línea proviene de stderr del paso 3 (2>>), que se añadió al archivo sin borrar las líneas anteriores.

Respuestas

  1. /root pertenece al superusuario. El proceso de ls corre con uid de estudiante, que no tiene permiso de lectura.
  2. > abre el archivo truncando; >> lo abre en modo append (agrega al final).
  3. Repetir el paso 1 con > borraría el contenido existente antes de escribir la nueva línea.

Síntesis técnica · Lo esencial de hoy

Mapa mental en 5 puntos

  • Terminal ≠ Shell: el terminal es el canal; el Shell es el intérprete.
  • Ciclo de un comando: tokenización → PATH lookup → fork/exec → syscall → salida.
  • PATH: lista de directorios buscados en orden; quien aparece primero, gana.
  • Flujos estándar: stdin (0), stdout (1), stderr (2) son descriptores de archivo; todos redirigibles.
  • Redirección: > trunca, >> agrega, 2> captura errores, /dev/null descarta.

Competencia adquirida

A partir de hoy, cada comando que ejecutes tendrá un significado arquitectónico claro: sabes en qué capa opera, cómo el SO lo resuelve y a dónde van los datos que produce.
