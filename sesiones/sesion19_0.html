Bloque A · Que es scripting y que no es

Definiciones de primera aparicion

  • Script: archivo de texto con instrucciones ejecutadas por un interprete (ej: Bash).
  • Interprete: programa que lee y ejecuta linea a linea (bash, pwsh, cmd).
  • Shebang: primera linea #!/bin/bash que define el interprete.
  • Idempotencia: ejecutar dos veces y mantener el mismo estado final correcto.
  • Exit code: numero de salida de un proceso. 0=exito; distinto de 0=error.

Diferencia clave

Un historial de comandos no es automaticamente un script: le falta validacion, manejo de errores, parametrizacion y una salida clara para diagnostico.

# Script minimo valido #!/usr/bin/env bash set -euo pipefail echo "Inicio $(date -Iseconds)" echo "Usuario: $(whoami)"

Bloque A · Variables y alcance: local vs entorno

Concepto tecnico profundo

  • Variable local: vive en el proceso actual del shell.
  • Variable de entorno: se exporta a procesos hijo y comandos invocados.
  • Subshell: proceso shell hijo; recibe entorno, no comparte cambios de regreso.
  • Expansion: sustitucion de $VAR por su valor en tiempo de ejecucion.
APP_ENV="dev" echo "$APP_ENV" # visible aqui bash -c 'echo "$APP_ENV"' # vacio export APP_ENV bash -c 'echo "$APP_ENV"' # ahora si: dev

Riesgo comun

Usar variables sin comillas rompe rutas con espacios y abre fallos por expansion no deseada. Regla operativa: citar siempre "$VAR", excepto cuando deliberadamente quieres separacion por espacios.

Para PowerShell la expansion segura usa "$var"; en Batch, "%VAR%".

Bloque B · Condicionales y decisiones confiables

if, test y case en Bash

#!/usr/bin/env bash set -euo pipefail RUTA="${1:-}" if [[ -z "$RUTA" ]]; then echo "Uso: $0 " exit 2 fi if [[ -d "$RUTA" ]]; then echo "Directorio valido" else echo "No existe: $RUTA" exit 3 fi case "${2:-audit}" in audit) echo "modo auditoria" ;; fix) echo "modo correccion" ;; *) echo "modo invalido"; exit 4 ;; esac

Diseno recomendado

  • Validar argumentos al inicio y terminar rapido si faltan.
  • Usar codigos de salida distintos por tipo de error.
  • Separar modo audit y fix para evitar cambios involuntarios.
  • Evitar if anidados de forma excesiva: usar funciones pequenas.

Bloque B · Iteracion: for, while y lectura robusta

Procesar colecciones sin romper datos

# Evitar: for f in $(ls) # rompe nombres con espacios # Caso para observar el problema mkdir -p demo_ls ; cd demo_ls touch "ok.conf" "mi archivo.conf" for f in $(ls); do echo "Archivo: $f" done # Salida tipica (incorrecta): # Archivo: mi # Archivo: archivo.conf # Archivo: ok.conf # Correcto para archivos reales: while + find + -print0 while IFS= read -r -d '' f; do echo "Procesando: $f" done < <(find . -type f -name '*.conf' -print0) # Salida correcta: # Procesando: ./mi archivo.conf # Procesando: ./ok.conf

Idea clave

Un script operativo debe sobrevivir a casos reales: nombres con espacios, caracteres especiales, rutas vacias, permisos insuficientes y ejecuciones repetidas.

Si tu logica funciona solo con nombres "limpios", aun no esta lista para produccion.

Solucion guiada 1

Script referencia (Bash)

#!/usr/bin/env bash # 1) Modo estricto: aborta en errores, variables no definidas y pipes fallidas set -euo pipefail # 2) Parametros de entrada y archivo de salida RUTA="${1:-}" SALIDA="reporte_inventario.txt" # 3) Validacion temprana: si falla, terminar con codigo 2 if [[ -z "$RUTA" || ! -d "$RUTA" ]]; then echo "Uso: $0 " exit 2 fi # 4) Funcion reutilizable para contar archivos por patron contar() { find "$RUTA" -type f -name "$1" | wc -l } # 5) Recoleccion de metricas de inventario TOTAL_DIR=$(find "$RUTA" -type d | wc -l) TOTAL_FILE=$(find "$RUTA" -type f | wc -l) N_SH=$(contar "*.sh") N_CONF=$(contar "*.conf") N_LOG=$(contar "*.log") { echo "Inventario: $RUTA" echo "Fecha: $(date -Iseconds)" echo "Usuario: $(whoami)" echo "Directorios: $TOTAL_DIR" echo "Archivos: $TOTAL_FILE" echo "*.sh: $N_SH" echo "*.conf: $N_CONF" echo "*.log: $N_LOG" } > "$SALIDA" echo "Reporte generado en $SALIDA"

Validacion de la solucion

  • Termina con codigo 2 si la ruta es invalida.
  • No rompe por espacios porque todas las rutas van con comillas.
  • Puede ejecutarse varias veces y siempre sobrescribe reporte consistente.

Bloque C · Funciones, parametros y codigos de retorno

Diseño modular de scripts

  • Una funcion debe hacer una sola tarea observable.
  • Recibe parametros posicionales ($1, $2, ...).
  • Retorna con return N (0 exito, otro valor falla).
  • El script principal orquesta funciones y decide salida final.
# Funcion de traza para mensajes consistentes con hora log() { echo "[$(date +%H:%M:%S)] $*" } # Verifica existencia de directorio; retorna 10 en caso de error asegurar_dir() { local d="$1" [[ -d "$d" ]] || return 10 } asegurar_dir "$RUTA" || { log "ruta invalida"; exit 10; }

Bloque Batch · Estructura, directivas y variables de entorno

Anatomia de un archivo .bat

  • @echo off: suprime la impresion de comandos; solo muestra la salida util.
  • REM texto: comentario; no se ejecuta ni se muestra en pantalla.
  • ECHO mensaje: imprime texto. ECHO. imprime una linea en blanco.
  • ECHO ON / ECHO OFF: activa o desactiva el eco de comandos desde el interior del script.
  • PAUSE: detiene ejecucion hasta tecla. PAUSE>NUL espera sin mostrar texto.
  • SET VAR=valor: define variable local; se accede con %VAR%.
  • %username%, %TEMP%, %DATE%, %TIME%: variables de entorno del sistema.
@echo off REM Script de identificacion del sistema SET NOMBRE=SistemaOS SET VERSION=1.0 ECHO Script: %NOMBRE% v%VERSION% ECHO Usuario activo : %username% ECHO Carpeta temporal: %TEMP% ECHO. ECHO Fecha: %DATE% Hora: %TIME% REM Pausa silenciosa: espera tecla sin mostrar mensaje PAUSE>NUL

Crear un .bat desde la terminal CMD

:: Crear un archivo escribiendo directamente en consola :: Ctrl+Z + Enter guarda el archivo copy con tiempo.bat date time :: (Ctrl+Z para guardar) :: Ejecutar el archivo creado tiempo.bat :: Editar con Notepad en cualquier momento notepad tiempo.bat

La extension .bat indica a cmd.exe que trate el archivo como script de procesamiento por lotes.

Automatizacion de tareas del sistema

:: Abrir sitio web en el navegador predeterminado START https://www.pascualbravo.edu.co :: Cargar tres sitios con espera de 6 s entre cada uno START https://wikipedia.com timeout /nobreak 6 START https://github.com timeout /nobreak 6 :: Opciones del comando SHUTDOWN shutdown /s /t 60 /c "Cerrando en 60 s" :: apagar shutdown /r /t 0 :: reiniciar inmediato shutdown /H /F :: hibernar (forzado) shutdown /l :: cerrar sesion shutdown /a :: cancelar apagado pendiente :: Liberar espacio y desfragmentar (START /WAIT = esperar) START /WAIT CLEANMGR /D D: START DEFRAG D: /U

Limpieza de archivos temporales

:: Temporales del usuario actual del C:\Users\%username%\AppData\Local\Temp /f /s /q rd C:\Users\%username%\AppData\Local\Temp /s /q :: Temporales globales de Windows del c:\Windows\Temp /f /s /q rd c:\Windows\Temp /s /q PAUSE

/f fuerza el borrado; /s recursivo en subdirectorios; /q silencioso. Los temporales de Windows requieren permisos de administrador.

Practica guiada Batch · Script de limpieza y mantenimiento

Enunciado de clase

Crear mantenimiento.bat que de forma automatizada:

  • Muestre usuario, fecha y hora al inicio.
  • Limpie la carpeta de temporales del usuario con flags correctos.
  • Ejecute el liberador de espacio en disco en C:.
  • Registre en pantalla el resultado de cada paso con mensajes claros.
  • Espere confirmacion del usuario antes de cerrar.
:: 1. Crear y editar el script con Notepad notepad mantenimiento.bat :: 2. Ejecutar el script (como Administrador si es necesario) mantenimiento.bat :: 3. Verificar que la carpeta Temp quedo vacia dir "%TEMP%" :: 4. Ejecutar por segunda vez y confirmar que no genera errores mantenimiento.bat

Criterios de validacion

  1. Primera linea es @echo off: sin eco de comandos.
  2. Cada seccion tiene comentarios REM y mensajes ECHO descriptivos.
  3. Limpieza usa /f /s /q: silenciosa, recursiva y forzada.
  4. Usa START /WAIT para que CLEANMGR termine antes de continuar.
  5. Termina con PAUSE para que el usuario revise la salida.

Solucion guiada Batch · mantenimiento.bat completo

Script referencia (Windows Batch)

@echo off REM ============================================= REM mantenimiento.bat REM Proposito: limpieza automatizada del sistema REM Ejecutar como Administrador REM ============================================= SET DISCO=C ECHO ===== Mantenimiento del Sistema ===== ECHO Usuario : %username% ECHO Fecha : %DATE% ECHO Hora : %TIME% ECHO. REM --- Paso 1: limpiar temporales del usuario --- ECHO Limpiando archivos temporales... del "C:\Users\%username%\AppData\Local\Temp" /f /s /q rd "C:\Users\%username%\AppData\Local\Temp" /s /q ECHO Temporales del usuario eliminados. ECHO. REM --- Paso 2: liberar espacio en disco --- ECHO Iniciando liberador de espacio en %DISCO%:... START /WAIT CLEANMGR /D %DISCO%: ECHO Limpieza de disco completada. ECHO. ECHO ===== Mantenimiento finalizado ===== PAUSE

Puntos de validacion docente

  • @echo off en la primera linea suprime el eco de todos los comandos.
  • Variable DISCO centraliza la unidad destino para ajuste sin editar la logica.
  • START /WAIT garantiza que CLEANMGR termine antes de continuar.
  • Las rutas entre comillas toleran espacios en nombres de carpeta.
  • PAUSE al final mantiene la ventana abierta para revisar la salida.

Practica guiada 2 · Auditoria y correccion por script

Enunciado de clase

Construir seguridad_webroot.sh que reciba una ruta y un modo:

  • audit: listar recursos con o+w y salir sin cambios.
  • fix: aplicar permisos seguros por tipo de archivo.
  • Generar log con fecha y resumen de acciones.
# 1. Crear estructura de webroot de prueba mkdir -p ~/webroot/html ~/webroot/conf ~/webroot/logs touch ~/webroot/html/index.html ~/webroot/html/app.js ~/webroot/html/main.css touch ~/webroot/conf/nginx.conf ~/webroot/logs/access.log # 2. Simular permisos inseguros (escritura para otros) chmod 777 ~/webroot/html/index.html chmod 777 ~/webroot/conf/nginx.conf # 3. Crear el archivo del script nano seguridad_webroot.sh # escribir la solucion aqui # 4. Dar permisos de ejecucion chmod 755 seguridad_webroot.sh # 5. Auditoria inicial: debe listar los recursos con o+w ./seguridad_webroot.sh ~/webroot audit # 6. Aplicar correccion de permisos ./seguridad_webroot.sh ~/webroot fix # 7. Auditoria final: no debe listar ningun recurso ./seguridad_webroot.sh ~/webroot audit # 8. Revisar el log completo generado cat seguridad_webroot.log

Reglas de correccion esperadas

  • Directorios: 755 en contenido publico, 750 en conf y logs.
  • Archivos .html/.css/.js: 644.
  • Archivos .conf/.log: 640.
  • Salir con codigo 20 si alguna aplicacion de permisos falla.

Solucion guiada 2

Script referencia completo

#!/usr/bin/env bash # 1) Modo estricto para evitar estado parcial en errores set -euo pipefail # 2) Parametros principales y bitacora RUTA="${1:-}" MODO="${2:-audit}" LOG="seguridad_webroot.log" # 3) Logger central: consola + archivo log() { echo "[$(date -Iseconds)] $*" | tee -a "$LOG" >/dev/null; } # 4) Validar argumentos y modo permitido validar() { [[ -n "$RUTA" && -d "$RUTA" ]] || { echo "Uso: $0 "; exit 2; } [[ "$MODO" == "audit" || "$MODO" == "fix" ]] || { echo "Modo invalido"; exit 3; } } auditar() { log "Auditoria en $RUTA" find "$RUTA" -perm -o+w -print | tee -a "$LOG" } corregir() { log "Aplicando reglas de permisos" find "$RUTA" -type d -path '*/conf' -exec chmod 750 {} \; find "$RUTA" -type d -path '*/logs' -exec chmod 750 {} \; find "$RUTA" -type d ! -path '*/conf' ! -path '*/logs' -exec chmod 755 {} \; find "$RUTA" -type f \( -name '*.html' -o -name '*.css' -o -name '*.js' \) -exec chmod 644 {} \; find "$RUTA" -type f \( -name '*.conf' -o -name '*.log' \) -exec chmod 640 {} \; log "Correccion finalizada" } # 5) Cualquier fallo inesperado termina con codigo 20 trap 'echo "Fallo en linea $LINENO"; exit 20' ERR validar # 6) Flujo principal por modo de ejecucion if [[ "$MODO" == "audit" ]]; then auditar else corregir auditar fi log "Proceso completado"

Salida final esperada

Despues de fix, el segundo audit no debe listar rutas con escritura para otros. El log debe registrar inicio, acciones y cierre con marca de tiempo.

Bloque D · Buenas practicas de produccion

Checklist tecnico operativo

Lectura practica: cada punto del checklist responde a una falla comun en scripts reales.

  • Idempotencia: si lo ejecutas dos veces, el resultado final sigue siendo correcto (no duplica ni rompe estado).
  • Dry-run: simula cambios y muestra "que haria" sin ejecutar acciones destructivas.
  • Logs: registrar fecha, accion, resultado y ruta para poder auditar y depurar.
  • Parametros explicitos: usar banderas como --path y --mode en lugar de valores fijos ocultos.
  • Minimo privilegio: correr como usuario normal y elevar privilegio solo en pasos puntuales.

Dry-run en 30 segundos

./script.sh --path /var/www --mode audit ./script.sh --path /var/www --mode fix --dry-run # Implementacion minima del flag DRY_RUN=0 [[ "$*" == *"--dry-run"* ]] && DRY_RUN=1 run() { if [[ "$DRY_RUN" -eq 1 ]]; then echo "[DRY-RUN] $*" else "$@" fi } # En vez de: chmod 640 "$archivo" run chmod 640 "$archivo" # Salida esperada en simulacion: # [DRY-RUN] chmod 640 /var/www/conf/app.conf

Regla de uso: primero --dry-run para validar impacto; luego ejecucion real sin ese flag.

Bloque D · Seguridad en scripting

Riesgos comunes que debemos prevenir

  • Inyeccion por entrada: concatenar parametros no validados en comandos.
  • Uso de eval: ejecutar texto dinamico con alto riesgo.
  • Path traversal: aceptar rutas como ../../ sin control.
  • Sobrepermisos: chmod -R 777 por conveniencia.
  • Silencio de errores: redirigir todo a /dev/null sin log.

Controles minimos recomendados

  1. Validar formato de entrada con regex o listas permitidas.
  2. Abortar en primer error inesperado (fail-fast).
  3. Limitar rutas de trabajo a un directorio base controlado.
  4. Evitar sudo dentro del script salvo caso justificado.
  5. Registrar evidencia para auditoria tecnica.

Hacia virtualizacion y aprovisionamiento

La virtualizacion no es solo crear una VM: requiere tareas repetibles de configuracion. El scripting que aprendimos hoy sera la base para:

  • Inicializar paquetes y usuarios en maquinas invitadas (ejemplo: actualizar repositorios y crear usuario operador).
  • Aplicar hardening basico al primer arranque (ejemplo: permisos en /etc y revision de servicios habilitados).
  • Recolectar diagnosticos de CPU, RAM y red de forma automatica (ejemplo: nproc, free -m, ip -br a).
  • Construir laboratorios reproducibles Host/Guest con una secuencia fija de preparacion y verificacion.

Preparacion sugerida

Objetivo del precheck: antes de crear una VM, confirmar que el host tiene recursos minimos para evitar fallos durante el aprovisionamiento.

# Precheck para validar recursos minimos antes de crear VMs cat > precheck_vm.sh << 'EOF' #!/usr/bin/env bash # Version de kernel activa echo "Kernel: $(uname -r)" # Numero de nucleos disponibles echo "CPU(s): $(nproc)" # Memoria total para estimar capacidad de virtualizacion echo "RAM MB: $(free -m | awk '/Mem:/ {print $2}')" EOF chmod 755 precheck_vm.sh ./precheck_vm.sh

Ejemplo de lectura rapida: si obtienes CPU(s): 2 y RAM MB: 2048, podrias ejecutar una sola VM ligera; con CPU(s): 8 y RAM MB: 16384, puedes planear un laboratorio con varias VMs.

Si trabajas en Windows, ejecuta este script en WSL o en una VM Linux para mantener comandos consistentes con la sesion.
