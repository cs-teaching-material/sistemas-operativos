Vocabulario confirmado

  • El Shell interpreta comandos; el kernel los ejecuta sobre el hardware.
  • Un comando sin ruta se busca en los directorios del PATH.
  • Los procesos heredan tres flujos: stdin, stdout, stderr.

Pregunta de enlace

Cuando ejecutas cat /etc/hostname, el Shell localiza el binario cat via PATH, lo ejecuta con fork+exec, y ese proceso hace una syscall para leer /etc/hostname del sistema de archivos. ¿Sabes identificar ya en qué capa opera cada parte? Eso es exactamente lo que reforzaremos hoy.

Bloque A · El Filesystem Hierarchy Standard (FHS)

¿Por qué existe un estándar?

El FHS (definido por la Linux Foundation) establece dónde debe vivir cada tipo de archivo en un sistema UNIX/Linux. Sin él, cada distribución organizaría el disco de forma diferente y los scripts serían incompatibles.

  • Permite a los administradores predecir la ubicación de archivos sin documentación.
  • Los instaladores de software saben exactamente dónde colocar binarios, libs y configs.
  • Los scripts de CI/CD y containers (Docker) dependen del FHS para rutas predecibles.

Directorios raíz más importantes

  • /bin, /usr/bin: binarios de usuario.
  • /sbin, /usr/sbin: binarios de administración.
  • /etc: archivos de configuración del sistema.
  • /home: directorios personales de usuarios.
  • /var: datos variables (logs, colas, bases de datos).
  • /tmp: archivos temporales (se borran al reiniciar).
  • /proc: sistema de archivos virtual; expone el estado del kernel en tiempo real.

Bloque B · Rutas absolutas y relativas

Definiciones

Ruta absoluta: comienza en la raíz del sistema (/). Es invariante: describe la misma ubicación sin importar el directorio de trabajo actual.

/etc/nginx/nginx.conf # siempre este archivo /home/juan/documentos

Ruta relativa: se interpreta desde el directorio de trabajo actual (CWD, Current Working Directory). Usa . (directorio actual) y .. (directorio padre).

documentos/informe.txt # relativo al CWD ../config/app.conf # sube un nivel, luego baja a config/ ./script.sh # archivo en el directorio actual

Regla práctica

En scripts de producción, siempre usa rutas absolutas. Evitas que el script falle dependiendo de desde dónde se lanza.

En trabajo interactivo, las rutas relativas son más rápidas de escribir.

~ es un atajo del Shell que expande al home del usuario actual: /home/juan. No es parte del sistema de archivos; el Shell lo reemplaza antes de pasar la ruta al kernel.

Comparación con Windows: en Linux una ruta absoluta arranca en /; en Windows suele iniciar con una unidad como C:\. Linux usa / como separador; Windows usa \, aunque PowerShell suele aceptar ambas formas en muchos comandos.

Bloque B · pwd, cd y ls: navegación básica

Los tres comandos de orientación

# pwd: Print Working Directory # Muestra la ruta absoluta del CWD $ pwd /home/estudiante # cd: Change Directory $ cd /etc # ruta absoluta $ cd documentos # ruta relativa desde CWD $ cd .. # sube un nivel $ cd ~ # vuelve al home $ cd - # vuelve al directorio anterior (historial) # ls: List directory contents $ ls # listado simple $ ls -l # formato largo (detallado) $ ls -la # incluye archivos ocultos (empiezan con .) $ ls -lh # tamaños en formato humano (KB, MB, GB) $ ls -lrt # orden inverso por fecha de modificación

El directorio oculto ..

Cada directorio siempre tiene dos entradas especiales:

  • . (punto): referencia al directorio actual.
  • .. (doble punto): referencia al directorio padre.

Los archivos que comienzan con . (punto) son ocultos por convención. El sistema no los lista con ls estándar; se necesita ls -a.

Navegar sin perder el norte

Preguntas de análisis

  1. ¿Cuál es la diferencia entre cd /etc y cd etc?
  2. ¿Qué muestra ls -lh | head -15 que ls solo no muestra?
  3. En el paso 5, ¿cuál es la ruta del directorio donde llegaste? ¿Por qué?
  4. ¿Qué cambia y qué no cambia entre pwd y Get-Location?

Salida esperada

$ pwd /home/estudiante $ cd /etc && ls -lh | head -5 total 1.2M drwxr-xr-x 3 root root 4.0K Apr 10 09:00 acpi -rw-r--r-- 1 root root 3.0K Jan 6 2020 adduser.conf drwxr-xr-x 7 root root 4.0K Apr 10 09:00 alternatives -rw-r--r-- 1 root root 401 Apr 10 09:00 anacrontab $ cd ~ $ pwd /home/estudiante $ cd /carpeta_inventada bash: cd: /carpeta_inventada: No such file or directory $ cd .. $ pwd /home PS> Get-Location Path ---- C:\Users\Estudiante PS> Set-Location C:\Windows PS> Get-ChildItem | Select-Object -First 3 Directory: C:\Windows Mode LastWriteTime Length Name ---- ------------- ------ ---- d---- 15/04/2026 08:00 addins d---- 15/04/2026 08:00 appcompat d---- 15/04/2026 08:00 Boot

Respuestas

  1. cd /etc usa ruta absoluta (funciona desde cualquier lugar). cd etc usa ruta relativa: busca etc dentro del CWD y falla si no existe ahí.
  2. ls -lh muestra permisos, dueño, tamaño legible, fecha y nombre. ls solo muestra nombres.
  3. Llegaste a /home: el padre de /home/estudiante es /home.
  4. pwd y Get-Location responden la misma pregunta: cuál es el CWD. La diferencia está en el ecosistema y el formato de salida: Bash devuelve texto plano; PowerShell devuelve un objeto con propiedades.

Bloque C · Inspección de archivos de texto

Cuatro formas de leer un archivo

# cat: vuelca el archivo completo en stdout cat /etc/hostname cat /etc/os-release # less: lector paginado interactivo # q=salir, /texto=buscar, G=final, g=inicio less /var/log/syslog # head: primeras N líneas (default 10) head -5 /etc/passwd head -20 /var/log/auth.log # tail: últimas N líneas tail -10 /var/log/syslog # -f: modo "follow" - muestra líneas en tiempo real tail -f /var/log/syslog # Equivalentes en Windows type C:\Windows\System32\drivers\etc\hosts Get-Content $env:WINDIR\System32\drivers\etc\hosts Get-Content .\app.log -Tail 10

¿Cuándo usar cada uno?

  • cat: archivos cortos (configs, scripts pequeños). Evitar con logs grandes.
  • less: archivos grandes. Permite navegar sin cargar todo en memoria.
  • head: revisar el encabezado de un CSV, ver las primeras entradas de un log.
  • tail -f: monitorear logs en producción en tiempo real.
  • type / Get-Content: en Windows cumplen la misma intención de inspección, aunque PowerShell opera sobre objetos y texto canalizado.

Bloque C · /proc: el kernel hablando a través de archivos

¿Qué es /proc?

/proc es un sistema de archivos virtual: sus "archivos" no existen en disco. El kernel los genera dinámicamente en memoria RAM cada vez que los lees. Es la forma en que Linux expone su estado interno como texto plano.

# Versión exacta del kernel en ejecución cat /proc/version # Información de la CPU cat /proc/cpuinfo | head -20 # Memoria disponible en tiempo real cat /proc/meminfo | grep -E "MemTotal|MemFree|MemAvailable" # Tiempo de actividad del sistema (uptime en segundos) cat /proc/uptime

Conexión con la Unidad 2

Cuando lees /proc/meminfo, el kernel VFS intercepta la llamada y devuelve los datos del subsistema de gestión de memoria que estudiamos (paginación, swap). No hay ningún archivo real en disco: es un "espejo" del estado del kernel.

Práctica guiada 2 · Inspección de configuración y logs

Escenario: diagnóstico de un servidor

Simula ser administrador que debe verificar el estado de un servidor recién encendido. Ejecuta los siguientes comandos y registra la información relevante; si trabajas en Windows, traduce primero la intención operativa al comando equivalente.

# 1. ¿Qué SO y versión corre el servidor? cat /etc/os-release | head -5 # 2. ¿Cuánta RAM tiene y cuánta está libre? cat /proc/meminfo | grep -E "MemTotal|MemAvailable" # 3. ¿Cuántos núcleos de CPU tiene? grep -c "^processor" /proc/cpuinfo # 4. ¿Cuándo fue el último login registrado? tail -5 /var/log/auth.log 2>/dev/null || \ tail -5 /var/log/secure 2>/dev/null # 5. Guarda el resumen en ~/informe_servidor.txt { cat /etc/os-release | head -3 echo "---" cat /proc/meminfo | grep MemTotal } > ~/informe_servidor.txt cat ~/informe_servidor.txt

Preguntas de análisis

  1. ¿De dónde viene la información que muestra /proc/meminfo? ¿Del disco?
  2. ¿Por qué el comando 4 usa 2>/dev/null || ...?
  3. ¿Qué hace el bloque { ... } > archivo en el paso 5?
  4. Si estuvieras en PowerShell, ¿qué comando usarías para leer un archivo y cuál para pedir ayuda de ese comando?

Como cierre formativo, comparar qué pasos dependen de Linux y cuáles representan una necesidad operativa común a cualquier sistema.

Solución guiada 2

Salida esperada de informe_servidor.txt

NAME="Ubuntu" VERSION="22.04.3 LTS (Jammy Jellyfish)" ID=ubuntu --- MemTotal: 16241504 kB

La salida exacta varía por sistema, pero la estructura es siempre la misma.

Respuestas

  1. /proc/meminfo viene directamente de la RAM del kernel, generado al vuelo. No hay lectura de disco. El kernel proyecta su estado interno como archivos de texto mediante el VFS.
  2. 2>/dev/null silencia el error si el archivo no existe en esa ruta. || ejecuta el segundo comando solo si el primero falló, intentando la ruta alternativa según la distribución.
  3. El bloque { cmd1; cmd2; } agrupa varios comandos y redirige la salida de todos ellos al mismo archivo con un único >.
  4. En PowerShell se usaría Get-Content para leer el archivo y Get-Help Get-Content para consultar ayuda. La intención es la misma que con cat y man en Linux.

Errores frecuentes y cómo corregirlos
ErrorCausaCorrección
No such file or directory con cd etc El estudiante usa ruta relativa creyendo que es absoluta. Solo funciona si el CWD es /. Usar siempre cd /etc (ruta absoluta) para llegar a directorios del sistema.
Asumir que ls en PowerShell es idéntico a GNU ls En PowerShell, ls es alias de Get-ChildItem; comparte intención, no implementación ni opciones. Si la plataforma es Windows, verificar el cmdlet real con Get-Help Get-ChildItem y no extrapolar flags de Bash.
cat /var/log/syslog bloquea la terminal El archivo tiene cientos de miles de líneas; cat vuelca todo y el scroll es inmanejable. Usar less /var/log/syslog o tail -100 /var/log/syslog.
ls etc da error pero ls /etc funciona La misma confusión de rutas absolutas vs relativas. ls etc busca etc en el CWD. Siempre pensar: "¿estoy usando ruta absoluta o relativa? ¿Desde dónde se interpreta?"
Confundir ~ con / El estudiante cree que ~ es la raíz del sistema. ~ es el home del usuario (/home/juan); / es la raíz del árbol de directorios.
No entender la columna de permisos en ls -l Los 10 caracteres (-rwxr-xr-x) no se interpretan correctamente. Recordar: posición 1 = tipo, posiciones 2-4 = dueño, 5-7 = grupo, 8-10 = otros. Se verá en profundidad en la sesión 18.

Síntesis técnica · Lo esencial de hoy

Mapa mental en 5 puntos

  • FHS: la estructura de directorios es un estándar. /etc = configuración, /var = datos variables, /proc = kernel en tiempo real.
  • pwd / cd / ls: los tres comandos de orientación. ls -l revela permisos, dueño, tamaño y fecha.
  • Ruta absoluta: comienza en /, siempre predecible. Ruta relativa: depende del CWD.
  • cat / less / head / tail: cada herramienta para un tamaño y propósito diferente. tail -f para monitoreo en vivo.
  • Equivalencias: dir, type, Get-Location y Get-Help persiguen necesidades equivalentes en Windows, aunque la sintaxis y la salida cambian.
  • /proc: sistema de archivos virtual. Los "archivos" son el estado del kernel en RAM; no hay disco involucrado.

Competencia adquirida

A partir de hoy puedes entrar a una terminal en Linux o Windows y no operar a ciegas: sabes dónde estás, cómo moverte, cómo leer archivos y cómo pedir ayuda al sistema antes de improvisar comandos.
